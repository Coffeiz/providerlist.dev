# PRD-PRICE-1 · 原币种计费与条件价格表达

> 状态：✅ 已实施 · 对应设计文档 v1.2 §5
> 实施范围：`packages/shared/src/pricing/`

## 1. 背景

价格数据是这个站点对用户最有价值、也最容易出错的部分。

三个具体的失败场景：

1. **浮点误差算错钱。** `0.1 + 0.2 === 0.30000000000000004`。
   阶梯价判断（输入 < 32000 且输出 ≥ 200）用浮点比较，边界会翻转。
2. **换算抹掉原价。** 把 CNY 折成 USD 展示，用户就看不到官方真实报价，
   也无法判断这是不是「国内比国际贵」。
3. **条件价格伪装成固定价。** 「短请求 ¥3.00，长请求 ¥5.00」被显示成
   「¥3.00」，用户按这个做成本估算必然低估。

## 2. 目标

1. 保留**官方原始结算币种**与条件规则；换算只能是派生参考视图。
2. 金额用**十进制字符串** + Decimal 运算，**禁止** JS `Number` 累计。
3. 条件价格**必须带条件展示**，不伪装成固定单价。
4. **计费单位归属具体计量项**，不默认整张表都是每百万 Token。
5. `null`（未取得可信值）与 `"0"`（确认免费）**严格区分**。

## 3. 非目标

- 不做精确账单模拟——MVP 只展示规则与适用条件。
- 不做汇率换算服务（许可未确认前只展示原币价）。
- 不做套餐价的「折算单价」——套餐有请求额度与用量门槛，不能除 Token 得出。

## 4. 验收标准

- [x] `addDecimal('0.1', '0.2')` → `'0.3'`（不是浮点误差）。
- [x] `compareDecimal` 对 `'3.00'` vs `'3.0'` 返回 0。
- [x] 金额字段必须匹配十进制字符串格式，否则校验失败。
- [x] 负数价格校验失败。
- [x] `currency` 必须是 ISO 4217 三字母码。
- [x] `effective_until` 早于 `effective_from` → 校验失败。
- [x] 条件价格解析出 `resolved` / `ambiguous` / `requires_usage_context` / `no_match` 四态。
- [x] 同优先级多条命中 → `ambiguous`，**不**随便挑一条。
- [x] `exclusive` 规则区间重叠 → 被检测出来（阻止发布）。
- [x] 条件字段缺失 → `requires_usage_context`（**不是** `no_match`）。
- [x] 展示格式为 `¥1.00 / 每百万 Token 输入`，**不**是 `¥1`。
- [x] 跨维度单位折算返回 `null`（秒不能折成 token）。
- [x] 条件价格与请求合法性判断**互不影响**。

## 5. 影响的契约

- `RateCard` / `PriceRule` / `RateItem` 的结构。
- `rate_items[]` 是唯一价格输入结构，旧版 `rates` 已迁移并移出契约。
- `PriceRule.conditions` 是隐式 AND 数组，元素使用 `{ field, operator?, value }` 形态；省略 `operator` 表示 `eq`，
  与 `ConstraintRule` 的 `[field, value]` 形态**语义隔离**。

## 6. 风险

| 风险 | 缓解 |
|---|---|
| 上游 USD 无官方 CNY 价 | 国内价记 `null`，**不**逆推；上游数值标「国际/未核实参考」 |
| 不同币种被直接比较 | 比较前强制检查币种一致；风险分级也在同币种内做 |
| 促销结束日期未知 | 填 `null` 并明确标记，**不**推断 |
| 规则语义被复用导致耦合 | 约束与价格用两套 AST 形态，各自求值 |

## 7. 验证

```bash
pnpm --filter @providerlist/shared/pricing test
```

关键用例：Decimal 精度边界、唯一命中 / 冲突 / 上下文不足三路径、
规则重叠检测、跨维度折算返回 null、上下文不足不等于无匹配。
