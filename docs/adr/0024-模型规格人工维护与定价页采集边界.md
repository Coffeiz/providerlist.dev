# ADR 0024：模型规格人工维护与定价页采集边界

- 状态：已接受
- 日期：2026-10-25
- 决策人：用户
- 补充：[ADR 0023](0023-模型发布事实与Provider供应事实分离.md)

## 背景

ADR 0023 将开发厂商发布的规范模型事实与 Provider Offering 供应事实分开，但尚未明确未来规格由谁采集与维护。现有适配器和 `data/model-specs/<provider-id>.json` 能自动从 Provider 文档采集或合并部分规格。各渠道文档可能描述渠道自身的 API 行为，自动合并容易把 Provider 特性当成开发厂商发布事实；网页结构变化也会使人工核对的字段被错误覆盖。

供应价格则必须持续跟踪，且结构化定价表能稳定提供 Provider 实际使用的模型 ID、币种和价格。需要明确两种数据的维护边界，并为定价页出现新 ID 提供人工处理入口。

## 决策

1. 规范 Model 的身份和详细发布规格由维护者人工录入 `data/models/`；每个非空事实都必须保留开发厂商官方来源及字段级证据。自动采集器、LLM 抽取和价格转换器不得写入这些规格字段。
2. 未来模型供应采集器只采集登记的定价页面中的精确 Provider 模型 ID、市场/Service、价格、币种、计量单位和价格条件，不采集模型详情。
3. Offering 保留 Provider 的 `provider_model_id`、`model_ref`、价格和供应状态；多个 Provider Offering 可关联同一规范 Model。
4. 成功解析定价页面后，如出现没有有效 `model_ref` 映射的 Provider 模型 ID，在仓库的 Issue tracker 自动创建或更新待处理 Issue，供维护者决定关联已有 Model、新增 Model、暂时未关联或排除该价格行。该 ID 不得自动成为规范 Model ID。
5. Issue 以 `provider_id + service_id + provider_model_id` 去重，并包含来源快照及价格摘要；同一 ID 的价格变更更新既有未结 Issue。来源抓取/解析异常不触发新模型 Issue。
6. 定价页条目的出现只按明确登记的来源规则作为供应观察，不因单次缺席退役；价格行无法证明当前供应时只形成候选。
7. 迁移现有模型信息时，完整盘点 Offering 与 `data/model-specs/` 中的每个 ID。开发厂商有证据的发布事实进入人工维护的 Model；渠道级事实保留在相应供应层；归属或身份不明的事实保留待核，不能为追求全量关联而猜测。

## 备选方案

- **继续由采集器抓取模型详情：** 更新速度较快，但不同 Provider 文档可能表达不同 API 行为，且难以保证详情属于开发厂商发布事实。
- **把定价页中出现的 ID 自动当成规范 Model：** 不采纳。Provider ID 可能是别名、路由名、版本标签或聚合商映射，字符串相同不证明身份相同。
- **人工跟踪定价和规格：** 规格部分采用人工维护；定价持续变化、字段较规整，适合采集器定期检查，因此不把价格也改为手工维护。
- **新 ID 只输出控制台 warning：** 不采纳。缺少持久化任务容易遗失，Issue 能承载身份判断、来源证据和解决状态。

## 后果

- 规范 Model 规格的权威来源明确，采集器不会静默修改或补全其事实。
- 规格资料会比自动爬取更新慢，需要维护者核验官方资料并更新 `verified_at`；未知和过期字段必须可见。
- 新 ID 可以从定价差异进入人工身份评审，但 Issue 建立不代表 Model 已确认或供应已发布。
- Issue 自动化必须有语义解析成功门槛和稳定去重键，避免来源结构变化造成噪声。
- 当前 `data/model-specs/` 与规格采集路径须先完成全量盘点、证据归属和迁移，再停用；迁移过程中保留可回滚来源。
