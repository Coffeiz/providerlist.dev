# ADR 0041：扁平供应状态与 Git 生成更新时间

- 状态：部分取代（更新时间方案由 ADR 0042 更新；能力状态由 ADR 0044 更新）
- 日期：2026-11-01

## 背景

Provider 源数据同时保存 Offering 状态和嵌套的生命周期对象；状态事件又单独存放在 `data/sources/lifecycle/` 并由离线状态机重新计算。事件文件需要维护主体引用、事件类型、观察时间和证据关联，日常数据变更成本较高。Provider 文件中的 `updated_at` 也需要人工维护，容易与实际数据合并时间不一致。

## 决策

1. Provider、Service、Offering 和 Service Capability 直接使用可选的扁平 `supply_status`：`active`、`deprecated`、`retired` 或 `unknown`。账号资格和地区限制仍由 `availability` 表达。
2. `deprecated` 和 `retired` 必须有 Provider 来源台账证据。状态由维护者审核并写入 Provider 源数据；单次抓取失败或目录缺席只生成复核提示，不自动更改状态。
3. 删除供应生命周期事件 Schema、事件目录和供应状态状态机。`data/ingestion-lifecycle/` 继续保留，它记录采集 PR 的处理过程，不再承载模型供应事实。
4. Provider 与 Model 源文件不保存更新时间。编译器从 Git 历史生成站点专用 `updated_at` 并嵌入对应数据集；具体方案见 ADR 0042。
5. Publish 检出完整 Git 历史以生成准确时间。临时或无 Git 历史的构建以 `generated_at` 作为回退时间。

> 本 ADR 的更新时间输出方式已由 [ADR 0042](0042-采集来源集中记录与更新时间生成.md) 更新。Service 与 Offering 的扁平 `supply_status` 决策仍有效；Service Capability 状态字段由 [ADR 0044](0044-独立能力作为当前目录记录不设状态字段.md) 取代。

## 影响

- TypeScript、JSON Schema、语义校验、IR 投影、编译数据集及前端筛选统一使用 `supply_status`。
- Provider 与 Model 更新时间的唯一生成来源是文件 Git 历史，不需要维护者编辑，也不新增 checked-in 的更新时间目录。
- 既有供应事件记录不再参与构建；非当前状态的来源依据保留在 Provider 来源台账中。

## 取代的决定

本 ADR 取代供应生命周期事件驱动状态机相关决定，包括 ADR 0011、0014、0015，以及 ADR 0025 中依赖事件状态机保存当前状态的实现要求。采集 PR 处理记录属于独立工作流，继续按现有规则保存。
