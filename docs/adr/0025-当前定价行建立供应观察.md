# ADR 0025：当前定价行建立供应观察

- 状态：已接受
- 日期：2026-10-25
- 决策人：用户
- 细化：[ADR 0024](0024-模型规格人工维护与定价页采集边界.md) 关于定价来源能否证明供应的规则

## 背景

模型规格由人工维护后，采集器的主要职责是跟踪 Provider 定价页中的当前模型 ID 和价格。如果这些价格行只能作为价格候选，仍需另找一个模型目录来源才能确认当前供应，容易让价格页明确列出的在售项目从公开供应目录中遗漏。现有生命周期契约已有 `observed_available` 事件，可表达带来源证据的首次供应观察。

另一方面，价格页可能保留历史、即将生效或已退役的行；列价也不能证明特定账号具备资格或 API 已调用成功。需要限定自动正向观察的范围和人工纠错方式。

## 决策

1. 对已登记为当前定价来源的页面，抓取和解析成功后，当前有效且语义完整的结构化价格行作为 Provider Offering 当前供应的正向观察，生成 `observed_available`，并在待审候选中标记 `lifecycle.stage: active`。
2. 供应观察基于 Offering 身份与定价行的 Provider ID、Service/市场及原始证据；`model_ref` 是否已映射不影响该供应判断。身份待确认仍需生成 Issue，但不能阻止已明确列价的 Offering 候选。
3. `active` 表示 Provider 的当前定价页面列出该供应项，不表示账号有权使用或 API 调用已实测；不得据此把未知 `availability` 改成可用。
4. 明确标记为历史、已退役或未来生效的行不是当前有效价格行，不触发 `observed_available`。价格页抓取失败、结构不完整或解析不确定也不触发状态变化。
5. 自动生成的候选仍须经 PR 人工审核后才进入正式目录。审阅者发现价格行并不代表当前供应时，可以在发布前排除该行或更正候选，必须记录理由和证据。若误标已发布，必须通过带证据且指向原 `observed_available` 的更正/撤回记录重新计算生命周期，保留原观测历史，不直接编辑 `dist/`。
6. 单次价格行缺席、来源失败或不完整不得将既有 Offering 标为退役；退役继续遵守现有生命周期状态机与证据要求。

本决策将 ADR 0024 中“只有单独批准的来源规则才把定价行用作供应观察”细化为：登记并审核为当前定价来源的有效价格行均可建立正向供应观察。ADR 0024 的人工 Model 规格边界、Issue 映射流程及其他决定继续有效。

## 备选方案

- **价格页只更新价格，另需独立模型目录确认供应：** 会漏掉定价页已明确列出的型号，并增加重复来源维护。
- **任何价格行都立即视为无条件可用：** 不采纳。历史行、未来生效行以及账号资格差异会被误解为当前可调用。
- **采集后无需 PR 自动发布：** 不采纳。页面解析正确不代表供应语义一定正确；人工审核是纠正误列的门槛。
- **价格行缺席一次就退役：** 不采纳。页面故障、区域差异或表格变化不能证明停止供应。

## 后果

- 定价页成为该 Provider 模型 ID、价格和当前供应正向观察的共同来源；模型规格仍只由人工维护。
- 新的有效价格 ID 即使尚未映射规范 Model，也能保留为 `active` Offering 候选，同时产生身份 Issue。
- Offering 生命周期 `active` 与账号/API 可用性仍然是不同事实。
- 数据政策和生命周期测试需要覆盖成功价格行、历史/未来行、解析失败、人工否决及单次缺席。
- 现有 lifecycle event 契约尚不能显式撤回一条错误的 `observed_available`；实现前须扩展契约或给出等价、可审计的重算机制。
