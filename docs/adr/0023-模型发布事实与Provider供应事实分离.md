# ADR 0023：模型发布事实与 Provider 供应事实分离

- 状态：已接受
- 日期：2026-10-25
- 决策人：用户

## 背景

同一开发厂商的模型可以通过多家 Provider 提供。若每个 Provider Offering 都复制开发厂商公布的型号规格，同一发布事实会被多次维护，容易漂移；如果直接把不同 Provider 的有效 API 行为合成一套“模型规格”，又会掩盖各渠道的价格、供应状态、模型 ID 和协议差异。

## 决策

1. 规范 Model 以开发厂商及精确发布型号/变体为身份，集中保存开发厂商明确发布的事实，并按字段保留证据。
2. Provider Offering 继续表达特定 Provider、Service/市场的供应项；保留 `provider_model_id`，并负责价格、可用性、生命周期等 Provider 供应事实。Offering 通过 `model_ref` 关联可确认的规范 Model。
3. 多家 Provider 提供同一个已确认型号时，多个 Offering 可以共享同一 Model 记录；该模型发布事实不复制到各 Provider。
4. Provider 的 Route/协议行为、账号资格、区域差异及报价仍按其供应层记录。Model 的发布能力说明不代表各渠道 API 都支持该能力。
5. 只有精确身份关系有证据时才建立映射。相似名称、相似 ID 或相同能力不够；不确定时保留未关联并供人工复核。
6. Provider 供应退役不退役或删除规范 Model。规范 Model 的引入及已有规格迁移按 [PRD-DATA-3](../_archived/prds/【已完成】PRD-DATA-3-规范模型注册表与Provider供应映射_cn.md) 实施。

## 备选方案

- **每个 Provider 保留完整规格副本：** 当前结构可以直接容纳，但重复事实需要多点维护，聚合渠道容易与开发厂商资料不一致。
- **把所有 Provider 的有效行为合成为一个 Model：** 不采纳。Provider 可能使用不同模型 ID、Route、参数映射或市场策略，合并会把渠道行为误写成模型固有属性。
- **只记录 Provider Offering，不建立共享 Model 身份：** 能保留供应事实，但无法可靠统计和查询多个 Provider 实际提供的同一个开发者型号，也无法消除规格副本。
- **按名称或字符串相似度自动匹配：** 不采纳。蒸馏版、兼容层、版本别名及同名模型会造成错误身份合并。

## 后果

- 开发者发布的可复用型号事实有单一维护位置，多个 Provider 的供应和定价仍可以独立变化。
- 必须建设 Model 契约、跨文件引用校验和公开静态数据输出，并迁移当前 Offering 规格及其证据。
- 身份证据不充分时允许未关联；目录不能为追求覆盖率而强行合并。
- 共享 Model 的规格可能与某 Provider API 的实际限制不同；使用方需按 Model 发布事实与 Route/Offering 事实各自理解。
- 公开 v1 的兼容策略需在实现前明确；此决策不授权静默破坏既有消费者。
