# ADR-0040 · ProviderList 长期订阅 API 路径

> 状态：已接受 · 日期：2026-10-31
> 取代范围：ADR-0037 规定的自定义查询路由路径，以及 ADR-0038 对该路由路径的引用；筛选、投影、缓存、币种与无状态约束继续有效。

## 背景

ProviderList 的 JSON Builder 会生成带用户筛选参数的 URL，供开发者长期订阅当前发布的数据。该 URL 是 ProviderList 对外提供的产品 API，需要使用清晰、稳定且能识别产品来源的正式路径。项目尚未正式上线，可以在首发前统一路径，无需维护旧地址兼容期。

## 决策

- 将唯一动态只读订阅端点定为 `GET /v1/providerlist.json`。
- 保留 ADR-0037 的参数白名单、结果结构、数据来源、大小限制和共享缓存行为；本次只更改路径与用户可见的端点名称。
- Builder 为当前选择生成该端点的查询 URL。端点仍从同次部署的静态数据集生成结果，不访问数据库或上游，不保存订阅配置，也不列入静态 Manifest。
- `/v1/query.json` 不作为别名维护；项目上线前统一使用新路径。
- `/v1/offerings.json` 继续表示完整的 Active Offering 清单，与可配置投影订阅端点用途不同。

## 备选方案

### 继续使用 `/v1/query.json`

名称准确表达查询动作，但没有体现这是 ProviderList 提供的长期订阅产品地址。

### 使用 `/v1/offerings/query.json`

这个端点生成的不只是 Offering 列表，还包括按 Provider 和市场组织的 API 与模型投影；该路径会让消费者误以为其响应是标准 OfferingList 子资源。

## 后果

- API 页面、Builder、Worker、本地开发中间件和当前契约文档必须一致使用 `/v1/providerlist.json`。
- 由于尚未正式上线，不提供旧路径重定向或双路由兼容。
- 该路径属于稳定 v1 请求入口；请求参数仍受白名单约束，响应版本跟随当前发布数据。
