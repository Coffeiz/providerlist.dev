# ADR 0042：采集来源集中记录与更新时间生成

- 状态：已接受
- 日期：2026-11-01
- 关联：[ADR 0029](0029-来源证据台账与公开数据分离.md)、[ADR 0041](0041-扁平供应状态与Git生成更新时间.md)

## 背景

Provider 和 Model 文件中的来源、字段证据及状态台账增加了维护步骤，也让人工贡献者需要同步修改多份文件。日常数据更新通常是一组事实的整体修改，GitHub PR 已能记录来源链接、审核和合并过程。

## 决策

1. `data/providers/` 和 `data/models/` 只保存业务事实及面向用户的官方文档链接，不保存字段级来源或证据引用。
2. 自动采集使用的固定来源 URL 与最近采集时间集中记录在 `data/collector/providers.json`。该表只服务自动采集；新增来源必须先登记在对应适配器的固定 HTTPS allowlist 中。
3. 抓取快照、哈希和机器证据只保留在候选及评审材料中。手动数据更新只需在 PR 模板中提供来源 URL 和改动说明，不维护来源 sidecar。
4. Provider 与 Model 源文件不手动维护更新时间。编译器从 Git 历史生成站点专用 `updated_at`，并直接写入对应站点数据集；不再生成独立 `updates.json`，也不把时间字段放入公开 API。
5. 删除旧 `data/sources/` 及其编译、验证和迁移依赖。`data/ingestion-lifecycle/` 仅用于记录采集 PR 的处理状态，不表达 Provider 或 Model 的供应状态。

## 后果

Provider 和 Model 更新只需修改对应事实文件；人工依据通过 PR 可读地审查。自动采集状态仍可按 Provider 查看，但不承担人工来源审计。发布构建需保留 Git 历史，以便生成站点更新时间。

该决策取代 ADR 0029 的字段证据 sidecar 方案，以及 ADR 0041 中通过独立 `updates.json` 发布站点更新时间的方案；ADR 0041 的扁平 `supply_status` 决策继续有效。
