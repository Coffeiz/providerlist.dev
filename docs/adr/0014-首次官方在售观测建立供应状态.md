# ADR 0014：首次官方在售观测建立供应状态

- 状态：已接受
- 日期：2026-10-24

## 背景

生命周期状态由事件求值，Provider 源数据不能直接手填 `active`。现有事件包括恢复、公告和退役等，
却没有描述“首次收录时，官方完整当前目录已明确列出该 Offering 在售”的事件。结果是新加入的
Offering 保持 `unknown`，无法进入有效供应统计，即使存在完整当前目录证据。

## 决策

增加 `observed_available` 事件。仅当当前生命周期为 `unknown` 时，该事件才将状态推进到 `active`。
它只表示官方当前目录列出供应，不代表 API 已探测，也不代表账号市场的调用资格；后两者继续由
独立的验证状态和 `availability` 表示。它不会覆盖已有的 `deprecated` 或 `retired` 状态。

事件必须引用字段证据，subject 必须指向真实 Offering；统一由既有生命周期状态机应用。

## 备选方案

- 在 Provider 文档直接填写 `lifecycle.stage=active`：会绕过事件驱动约束，不采用。
- 用 `restored` 表示首次发现：语义错误，因为不存在此前退役或缺席后恢复的事实，不采用。
- 继续保持 `unknown`：会让有官方明确在售证据的首批 Offering 无法计入当前供应，不采用。

## 后果

- 新 Provider 可通过“官方完整当前目录 + 证据引用 + `observed_available` 事件”进入有效供应统计。
- 自动化只能在候选中提出该事件；其正式事件和 Offering 仍须经过 PR 审阅。
- 此事件不应被用于不完整目录、搜索结果或无法判定当前状态的页面。

## 实施

同步更新 `packages/schema` 生命周期事件契约、生命周期求值器、`docs/data/schema.md` 和
`docs/data/data-policy.md`。MiniMax 首次导入使用该事件记录 30 个中英文站当前目录 Offering。
