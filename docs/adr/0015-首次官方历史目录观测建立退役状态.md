# ADR 0015：官方目录明确退役状态观察

- 状态：已接受
- 日期：2026-10-26

## 背景

生命周期状态由事件求值。官方目录可能把型号明确标记为 `Shut down`、`已下线` 或 `Retired`，但
本项目此前的供应观察可能较旧，且官方目录未提供实际停服生效日期。仅靠
`confirmed_retired`（要求生效日期）无法表达这一事实，导致型号无法进入正式数据，详情页的
“显示已退役”开关也无记录可显示。

## 决策

增加 `observed_retired` 事件。根据明确的官方目录停服标记将状态推进为 `retired`；当其观察晚于该
Offering 最后一次 `observed_available` 或 `restored` 时，也可以覆盖较旧的 active / deprecated 状态。
该事件记录本项目观察到官方停服标记的时点，不声称知道实际停服日期；没有来源明确给出退役生效日期时，
不填写 `retire_at`。较新的供应中/恢复观察可以恢复为 active。

从当前目录消失、抓取不完整或分页遗漏不能产生 `observed_retired`，仍按既有缺席规则处理。
事件必须有证据引用，并指向正式 Offering。

## 备选方案

- 用 `confirmed_retired` 并把抓取时间填入 `effective_at`：会把观察时间伪装成供应商退役生效时间，不采用。
- 在 Provider 文档直接手填 `lifecycle.stage=retired`：会绕过事件驱动约束，不采用。
- 不导入历史型号：详情页无法展示官方明确列出的历史供应记录，不采用。

## 后果

- 正式目录可保留官方明确标记为已退役的模型，默认仍隐藏；启用“显示已退役”后可见。
- 实际退役日期未知时保持未知，不影响发布时间等独立字段。
- 该事件不能覆盖更新的供应中或恢复观察。

## 实施

同步更新生命周期事件求值器、领域测试与数据政策。官方目录中明确标记为停服的 Offering 使用该事件；
单纯缺席仍不构成退役证据。发布日期、缓存等已有字段仍按各自来源单独保存。
