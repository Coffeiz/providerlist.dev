# ADR 0027：首次上线前直接定义 v1 模型注册表契约

- 状态：已接受
- 日期：2026-10-25
- 决策人：用户
- 补充：[ADR 0023](0023-模型发布事实与Provider供应事实分离.md)
- 明确：[ADR 0024](0024-模型规格人工维护与定价页采集边界.md) 中注册表源目录的实际文件形状

## 背景

DATA-3 将开发厂商发布的模型身份与规格从 Provider Offering 拆到全局 Model 注册表。ProviderList 页面和公开数据 API 尚未上线，因此尚无需要继续支持的外部 v1 消费方。保留旧 Offering 规格字段并行输出会造成两个事实来源，也会让采集、校验和页面继续承担兼容分支。

## 决策

1. ADR 0024 中的逻辑注册表目录落实为单一源文件 `data/models.json`，并以 `/v1/models.json` 作为公开路径。
2. Provider Offering 的 `model_ref` 是必填字段，身份未能确认时写 `null`。
3. `model_type`、开发厂商发布的 modalities、limits、capabilities、release date 等 Model 事实只通过注册表发布；Provider API 行为、Route、价格、供应状态、账号可用性与独立 Service Capability 仍保留在 Provider 供应层。
4. 首次正式发布仍使用 `/v1/` 和 `schema_version: 1.0.0`。不发布 `/v2/`，不保留旧 Offering 字段的兼容投影，也不添加旧结构读取分支。
5. 本决定只确定尚未上线的首次公开契约，不改变上线后的版本兼容承诺；上线后若需破坏性调整，按届时生效的版本策略另行决策。

## 备选方案

- **同步发布 `/v1/` 与 `/v2/`：** 不采纳。当前没有上线中的消费者，双份数据会引入重复事实和长期维护负担。
- **继续保留 Offering 规格的兼容投影：** 不采纳。投影可能与共享 Model 不一致，也会掩盖唯一事实来源。
- **将路径直接升为 `/v2/`：** 不采纳。当前仍处于首次 v1 契约设计阶段，版本号应对应首次正式发布的契约。

## 后果

- Provider Offering schema 可直接收紧 `model_ref` 并移除已迁移的 Model 规格字段。
- 构建器、目录索引、统计和前端必须一并读取 Model 注册表；静态公开数据与 Schema 同时发布。
- 本次上线前无需迁移兼容窗口；此决定不表示 API、Route、Provider/Service 能力或 Plan 采集器需要改写。
