# ADR-0012 · 中性单色玻璃方向与令牌数量约束

> 状态：已接受 · 日期：2026-10-23

## 背景

项目最初的 demo 视觉层是**扁平中性灰 + 靛蓝品牌色**，照设计文档 §3.6
「轻量开发者目录」的文字描述实现，没有任何材质感。评审时判定为
「太素、缺精致度」。

用户随后提供了两版 GPT 生成的视觉参考稿：

- `providerlist_cards` —— v1.3 最终态：中性单色 + 克制玻璃 + 三列卡片网格。
- `providerlist_tokens_v1.3` —— 独立的令牌页样板：目录 + 编号章节 +
  真实中文字样 + 组件预览 + 开发交付区。

参考稿的价值不在于「有玻璃」，而在于它暴露了我们原方案的两个结构问题：

1. **颜色令牌失控**——`gray` 16 档 + `brand` 10 档 + 4 条状态各 5 档 = **46 个**
   原始颜色令牌。数字刻度（`--pl-gray-50`）会诱使人一直加档，
   最后没人说得清「`--pl-gray-300` 到底是哪个灰」，每个组件各挑一个，整套系统就散了。
2. **页面结构重装饰**——原首页有一整块 Hero 与四张玻璃统计卡，
   信息密度被稀释。参考稿是**内容优先**：页头 + 搜索 + 筛选条 + 卡片网格。

## 决策

### 1. 视觉方向：中性单色 + 克制玻璃

- **取消彩色品牌色**。层级改由「墨色反色」建立（`--pl-bg-inverse`）。
  页面里唯一有彩色的只剩状态语义色，读数时颜色不会被误当成装饰。
- **玻璃只有两档**（普通 / 实底），只做一层背景模糊。
  档位一多，叠层时后层会被前层压出色阶，页面会越刷越浑。
- **玻璃只给「可点击的实体」**——卡片、浮层、顶栏。
  数字、统计、表格用留白与边框，不用玻璃面。
- 顶栏从「贴边横栏」改为**悬浮玻璃条**（四周留白，从页面里浮起来）。
- 页面标题区**不超过一屏**，统计数字用分隔线而不是玻璃卡片块。
- 必须支持 `prefers-reduced-transparency`：玻璃层退化为实底，
  否则在「降低透明度」的系统设置下会变成一堆糊字。

### 2. 令牌数量约束（硬性）

- **每条色阶最多 3 档**，命名用语义词（`-soft` / `-medium` / `-hard`），
  **不用数字刻度**。
- **每类刻度最多 5 档**（间距、圆角、字号、字重），同样用语义词。
- 语义层令牌是**角色**不是色阶：一个角色一个值，不成组。

当前规模：5 条色阶（surface / ink / success / warning / danger）× 3 档 =
**15 个原始颜色令牌**，改造前是 46 个。

**为什么数字刻度不行**：数字刻度没有「上限」的语义。`--pl-space-16` 不够用就加
`--pl-space-18`，`--pl-gray-50` 不够用就加 `--pl-gray-25`——档位只增不减。
语义词命名会**逼你做取舍**：真的需要第 4 档灰，说明缺的是语义角色，
在语义层加角色（`--pl-bg-muted`）而不是给原始色板加一档。

### 3. 删掉的状态色

`info`（青）被删除，Operation 标签改用 `neutral`。理由：
**分类标签不是状态**，不该占用彩色通道——彩色通道留给真正的供应状态，
这样一眼扫过去只有状态色在跳。

`brand` 徽章变体改名为 `inverse`（墨色实底），并且**只留给信任信号**
（「官方接入」）。它是全站除主按钮外唯一的实心块，不能被普通标签占用。

### 4. `/design` 页按参考稿重做

左侧 sticky 目录 + 右侧 6 个编号章节（色板 / 表面与玻璃 / 字体排版 /
间距与圆角 / 组件预览 / 开发交付）。

- 字号样例用**真实中文文案**，不用 token 名——token 名只能证明「这一档存在」，
  中文样例才能让人判断这一档在正文里读起来是什么感觉。
- 组件预览**直接用站点的真实组件**（`ProviderCard` / `StatusBadge`），
  不是重画一遍——重画会与实现脱节，这正是 ADR-0008 要避免的事。
- 色卡/语义角色/圆角块**点击复制**其 CSS 声明。

## 备选方案

### A. 直接采用参考稿的令牌粒度

**不选**：`providerlist_tokens_v1.3` 用了 `gray-50…950`（11 档）与
`space-1…12`（12 档）。用户明确要求「令牌不要那么多细分，保持当前细分」——
这与 ADR-0012 §2 的约束一致。参考稿借它的**版式与交互**，不借它的**粒度**。

### B. 保留靛蓝品牌色 + 叠加玻璃

**不选**：彩色品牌色与彩色状态色同时存在时，两者会争夺注意力——
用户看一个「即将退役」的橙色徽章时，会先注意到页面上还有一抹靛蓝，
状态反而不是第一眼读到的。取消品牌色让「有颜色 = 有状态」成为可靠信号。

### C. 大面积毛玻璃（多档透明度 + 强模糊 + 彩色辉光）

**不选**：这是 Gugu-web 那类 ToC 产品的做法。ProviderList 是工具型目录，
信息密度优先；玻璃做多了会让表格、代码、约束这些**需要精确阅读**的内容
变得难以聚焦。玻璃在这里只能是「表层材质」，不能是「视觉主角」。

## 后果

**好处**：
- 原始颜色令牌 46 → 15，新增颜色的决策成本大幅下降。
- 数字刻度消失后，「这个颜色是什么语义」一眼可辨。
- 「有颜色 = 有状态」成为可靠信号，扫读效率提升。
- `/design` 页用真实中文样例与真实组件，能真正用来判断读感，而不只是查表。

**代价**：
- 一次性重命名了约 550 处令牌引用。批量替换**必须**按键长倒序做正则
  （否则 `--pl-space-1` 先命中 `--pl-space-12` 的前缀），
  且必须是**单遍**的（否则 `--pl-text-xl → --pl-text-lg` 会继续被改成
  `--pl-text-md`）。这次改造就踩过这两个坑。
- 暗色主题下中性色阶必须整体翻转——「原始层不变」的旧表述已作废，
  ADR-0008 已补修订。
- 间距刻度最大只到 32px，大幅留白需要用结构（分节、分栏）而不是加刻度档位。

**新增的约束**：
- 新增色阶或刻度前**必须**过数量约束。超过上限时，在语义层加角色。
- 改令牌后必须跑一次**引用一致性检查**：漏定义的令牌在 CSS 里静默失效
  （`var(--pl-xxx)` 取不到值就回退到继承值），肉眼很难发现。
