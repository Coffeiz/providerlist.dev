# ADR 0036: Publish the complete canonical Model registry

- Status: Accepted
- Date: 2026-10-30
- Supersedes: the public-resource scope described in PRD-API-1 where `/v1/models.json` was omitted in favor of type-filtered lists only.

## Context

ProviderList has two related but distinct facts: canonical Model identity/specification and current Provider supply. A Model may be known and documented even when no currently reviewed active Offering references it. Consumers that need the complete model catalog should not have to infer it by joining Offering data or enumerate only active supply.

The site already builds an internal `ModelRegistryDocument`; the public API previously exposed only per-type `ModelList` resources, filtered to models referenced by reviewed active Offerings. Publishing the full registry requires preserving that useful filtered endpoint while making the complete model-only resource explicit.

## Decision

Publish `GET /v1/models.json` as the complete canonical `ModelRegistryDocument`, built from `data/models/`. It contains model facts only and omits internal sources, evidence, and evidence reference IDs. Its inclusion is independent of Provider supply status.

Keep `GET /v1/models/by-type/{type}.json` as a convenience projection containing only canonical Models referenced by at least one reviewed active Offering. Keep Provider and Offering resources governed by their existing reviewed-supply rules.

Include the registry in the current public manifest, its schema publication, and immutable version snapshots. The canonical model registry schema is `/v1/schema/model-registry.schema.json`.

## Alternatives considered

1. Keep only type-filtered lists. This makes the complete model catalog unavailable and conflates model existence with current reviewed supply.
2. Embed all model facts in Provider or Offering resources. This duplicates canonical facts across providers and makes consumers reconcile inconsistent copies.

## Consequences

- Consumers can download all canonical Model facts from one stable endpoint without treating them as currently supplied.
- A model may appear in `/v1/models.json` while being absent from active Provider and Offering resources; this is intentional.
- Type-filtered lists remain useful for current-supply browsing and do not change their active-review filtering.
- Public ModelRegistry output still excludes internal evidence ledgers and provenance identifiers.
