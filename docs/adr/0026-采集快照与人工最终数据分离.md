# ADR 0026：采集快照与人工最终数据分离

- 状态：已接受
- 日期：2026-10-25
- 决策人：用户
- 细化：[ADR 0024](0024-模型规格人工维护与定价页采集边界.md) 的人工 Model 维护边界及 [ADR 0025](0025-当前定价行建立供应观察.md) 的定价采集工作流

## 背景

采集器需要判断上游价格页等来源是否发生变化，并为变化生成可审核的 PR。若采集器将最终 Provider/Model 文件或公开目录当作比较基线，人工调整最终数据后，机器可能把人工编辑误判为漂移、冲突或需要覆盖的内容。最终数据也可能包含候选来源未披露的事实，不能用采集器的局部快照重建。

需要将“来源观察变化”与“最终目录变化”拆成两个独立流程：采集器拥有来源快照与候选，维护者拥有最终事实。

## 决策

1. 每个采集来源单独维护最近一次完整成功观察；采集器只比较该来源的新观察与自身基线，不读取最终 Model/Provider 数据、公开产物或页面展示结果来检测变化。为判断定价 ID 是否已有 `model_ref`、从而创建未映射 ID Issue，可只读查询当前 Model 注册表和映射；该查询不得参与快照差异计算或产生最终数据写入。
2. 原始快照 hash 用于追溯，稳定语义指纹用于识别事实变化。非语义的排版、时间戳和顺序变化不单独触发业务 PR。首次完整观察建立基线并给出初始候选。
3. 只有成功且完整的来源观察相对自身基线发生语义变化，才创建或更新来源专属 PR。机器生成的 PR 内容仅包含来源候选差异、证据与必要的快照元数据；不得自动转换并覆盖最终 Model、Provider 或生命周期文件，也不得写入 `dist/`。
4. 成功观察基线与人工评审决策基线分开维护。未决 PR 存在时，后续来源变化更新同一 PR，并保留尚未获得人工决定的累计变化；只有明确接受、拒绝或取代候选后，才推进评审决策基线。
5. 维护者可直接修改最终数据。人工最终数据的变化不改变采集器基线，也不触发采集 PR；上游变化 PR 不以最终数据状态决定差异或覆盖人工编辑。
6. 评审者决定接受、修正或排除候选。需要更新最终数据时，由人类在 PR 中编辑正式源文件并附理由/证据；合并后的最终数据仍须通过 Schema、语义校验及现有发布流程。
7. 抓取失败、解析失败或不完整观察不得推进成功观察基线、判作无变化、清空 Offering 或产生退役结论。单次来源缺席继续遵守生命周期政策。
8. 本流程并入 PRD-DATA-3 的 Model 注册表及定价供应迁移。现行 v1 转换器在迁移完成前仍按现有迁移期规则运行；迁移验收后由本决策取代其“最终文件自动转换基线”作为变化判定方式。

## 备选方案

- **对比公开最终目录与新候选：** 不采纳。人工最终编辑可能被误判为自动漂移；采集来源也不足以重建全部最终事实。
- **采集器依据候选自动重写整份 Provider 文件：** 不采纳。会把来源所有权和最终数据所有权混在一起，并可能覆盖人工修改。
- **完全不比较，任何抓取都开 PR：** 不采纳。排版与抓取元数据会产生噪声，无法明确区分实际来源事实变化。

## 后果

- 来源快照基线与最终公开数据有各自的所有权和变更轨迹；机器 PR 提供来源变化证据，最终目录更新由人工决定。
- 同一事实可能同时出现在候选和最终数据中，但候选不是最终数据的镜像，也不通过对账自动同步。
- 需维护每个来源的成功观察基线与语义指纹，并确保只有完整成功观察可推进基线。
- 工作流自动生成的 PR 不再直接携带最终目录机器改写；审核者需在评审 PR 中明确编辑最终源数据。
