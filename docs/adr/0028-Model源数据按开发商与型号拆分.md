# ADR 0028：Model 源数据按开发商与型号拆分

- 状态：已接受
- 日期：2026-10-25
- 决策人：用户
- 取代：[ADR 0027](0027-首次上线前直接定义v1模型注册表契约.md) 第 1 项关于单一源文件的目录决定；不取代其中有关首次公开 v1 契约的决定

## 背景

DATA-3 已建立全局 Model 注册表并迁移了 Provider Offering 的身份引用。单一 `data/models.json` 同时容纳所有开发商和型号，逐型号编辑、审核与冲突定位不够清晰。用户确定源目录应按开发商分组、每个型号单独维护；公开 v1 注册表仍需保持全局可查询。

## 决策

1. 每个 Model 源文件位于 `data/models/<developer_id>/<model>.json`，文件名使用精确 Model ID 尾段，尾段中的点号转换为连字符。
2. Model 事实文件只保存 `{ "model": Model }`；来源与字段证据单独保存在 `data/sources/models/<developer_id>/<model>.json` 台账中，以 JSON Pointer 绑定到事实字段。一个 Model 对应一份事实文件和一份台账。
3. 编译器从两级目录加载事实文件和对应台账，检查目录与 `developer_id`、文件名与 Model ID 一致，拒绝缺失/错配台账、重复 Evidence ID 和冲突 Source ID，然后恢复证据关联并汇总所有 Model。
4. 公开数据保持 `/v1/models.json` 与 `ModelRegistryDocument` 结构；本次只改变人工源数据布局，不引入 v2、兼容投影或运行时文件读取。
5. 不再维护 `data/models.json` 聚合源文件；聚合只发生在校验/编译过程和公开静态产物中。
6. DATA-3 迁移完成后，删除旧 `data/model-specs/` 源目录与其运行时读取逻辑；其中 Model 发布事实归入逐型号 Model 文件，API Operation 输入/输出继续归 Provider 文件和 Provider 适配器。

## 备选方案

- **继续使用单一 `data/models.json`：** 不采纳。单型号更改会使大型共享文件产生无关 diff，不利于并行评审和证据审阅。
- **将来源证据嵌入每个型号事实文件：** 不采纳。事实层与内部溯源台账分离，避免公开数据结构带入内部证据字段；编译前由一对一台账校验关联。
- **按开发商目录维护单份 registry JSON：** 不采纳。一个开发商目录仍会形成较大集合文件，未满足逐型号独立评审的目标。

## 后果

- 新增型号时需新增一个开发商目录内的 JSON 文件；删除/改名需通过普通数据评审，并保持 Offering 引用一致。
- 校验和构建必须从目录聚合，且不得因文件枚举顺序改变公开内容或数据版本。
- 人工源文件与 `/v1/models.json` 的职责分离：前者按型号评审，后者为全局发布视图。
