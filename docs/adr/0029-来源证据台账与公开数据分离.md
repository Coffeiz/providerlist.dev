# ADR 0029：来源证据台账与公开数据分离

- 状态：已被 ADR 0042 取代
- 日期：2026-10-25
- 决策人：用户
- 取代：[ADR 0028](0028-Model源数据按开发商与型号拆分.md) 第 2–4 项中将证据与事实放在同一型号文件、并将其发布为公开契约的决定；不改变一型号一事实文件的目录决定。
- 关联：[PRD-DATA-3](../_archived/prds/【已完成】PRD-DATA-3-规范模型注册表与Provider供应映射_cn.md)

> 本 ADR 的 sidecar 台账决策已由 [ADR 0042](0042-采集来源集中记录与更新时间生成.md) 取代。此文仅保留历史背景。

## 背景

Provider 和 Model 的来源/证据对象、字段引用曾直接嵌在事实 JSON 中，并随完整 Provider 文档和 Model 注册表公开。使用者需要的是 Provider 官方文档导航与当前业务事实；内部采集 URL、内容哈希、字段核验记录和引用 ID 属于维护及审计台账。两类数据混放使公开载荷变大，也把内部记录格式变成消费者负担。

## 决策

1. Provider 和 Model 的业务事实分别保存在 `data/providers/`、`data/models/`；其来源、Evidence、核验状态和来源引用统一迁入 `data/sources/providers/`、`data/sources/models/` 对应台账。
2. 台账以 `subject_ref` 绑定 Provider/Model，并用 JSON Pointer 记录来源引用对应的事实字段；原始快照与候选仍归 `data/upstream/snapshots/` 和 `data/candidates/`，生命周期事件仍归 `data/sources/lifecycle/`。
3. 编译器读取台账恢复内部交叉引用，执行现有来源、字段证据及生命周期校验；来源记录缺失或主体不匹配时构建失败。
4. `/v1/providers/{id}.json`、`/v1/models.json`、摘要索引和目录视图不输出 Source、Evidence、字段来源/证据引用及来源类别摘要。
5. Provider、Service、Endpoint、Route 和 Capability 上面向使用者的官方文档链接仍属于公开事实数据，继续保留；文档导航不能替代内部字段证据。
6. 来源台账不是网站 API，不进入发布产物；消费者仅凭公开事实和官方文档链接即可使用数据。

## 备选方案

- **继续在公开 Provider/Model JSON 发布全部证据：** 不采纳。消费者无需内部核验表，且字段证据与事实结构耦合。
- **删除来源/证据记录：** 不采纳。违反字段可追溯要求，生命周期审计也失去依据。
- **只保留 Provider 文档 URL 并用其代替字段证据：** 不采纳。页面链接不能说明每个字段对应的具体位置、抓取版本和核验结论。

## 后果

- Provider/Model 事实文件更聚焦，公开 JSON 不携带维护台账。
- 数据评审仍可审计每个字段依据；维护者需要同时修改事实文件及其来源台账。
- 公开 Schema 与返回数据不再把来源台账当作必需字段；未来新增事实必须在台账记录证据关联。
- 下载 JSON 的用户仍可访问 Provider 官方文档，但不能从公开 JSON 读取项目内部抓取时间、哈希或字段核验记录。
