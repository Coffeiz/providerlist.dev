# 仓库脚本约定

本目录存放仓库维护、校验和构建脚本。脚本按主要职责分组，避免把不同生命周期的工具堆在同一层。

## 目录

| 位置 | 职责 | 约定 |
|---|---|---|
| `ci/` | CI 静态门禁和对应回归测试 | 不访问真实网络，不写正式数据或发布目录；失败时给出文件、字段和修复方向 |
| `build-release.mjs` | 合并构建产物 | 只处理流水线产物，不手工改写源数据 |
| `secret-scan.mjs` | 敏感信息扫描 | 本地与 CI 共用，命中信息必须遮蔽敏感内容 |
| `licenses/` | 第三方依赖许可证清单生成与策略检查 | 从已安装依赖生成可审阅清单；CI 只读核对已提交清单的许可证策略 |

新增脚本时按职责归类。CI 专属校验放入 `ci/`；被本地开发命令和 CI 共用的通用工具留在其职责目录或现有入口，并通过 `package.json` 暴露稳定命令。

## CI 脚本约定

- 每项检查由仓库根 `package.json` 暴露稳定命令，脚本路径基于自身文件位置解析，不依赖调用者的当前目录。
- 输入限于仓库内的源文件或构建产物；不得抓取实时官方页面、读取本机凭据或依赖不可复现的外部服务。
- 违反规则时返回非零状态，并指出违反规则的文件和字段；通过时输出简短结果。
- 可独立验证的规则应配套回归测试，测试与脚本放在同一目录。
- 根 `package.json` 负责提供稳定命令；GitHub Actions 调用 package script，不直接耦合脚本文件的内部实现。
- CI 检查保持只读。需要生成候选或发布产物的工作应由对应的流水线负责。

当前 CI 检查：

| 命令 | 脚本 | 保护的规则 |
|---|---|---|
| `pnpm check:page-links` | `ci/check-page-links.mjs` | 页面按钮和文档链接不得直接指向 `.md` 抓取文件 |
| `pnpm licenses:check` | `licenses/check-licenses.mjs` | 已提交清单不得包含阻断策略中的许可证，且依赖清单不得缺少直接依赖 |

单独运行规则测试：

```bash
node --test scripts/ci/*.test.mjs
```
